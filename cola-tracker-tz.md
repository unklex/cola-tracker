## 1. Описание проекта

Ты будешь создавать **защищённый сервер (бэкенд)**, который хранит информацию о том, сколько Кока-Колы выпили дети. Твой сервер будет:
- Получать запросы от мобильного приложения на Android
- Проверять, что запросы идут от нашего приложения (через токен)
- Отправлять данные или сохранять новую информацию
- Хранить фотографии детей

### Что такое API?

**API (Application Programming Interface)** — это способ общения между программами. В твоём случае:

1. **Мобильное приложение (клиент)** отправляет запрос: _"Дай мне список детей"_
2. **Твой сервер (API)** проверяет токен и отвечает: _"Вот список детей с их данными"_

### Как работает REST API?

REST API использует **HTTP-запросы** (как браузер открывает сайты):

- **GET** — получить данные (_"покажи мне что-то"_)
- **POST** — создать новые данные (_"добавь это"_)
- **DELETE** — удалить данные (_"удали это"_)
- **PUT** — обновить данные (_"измени это"_)

Каждый запрос идёт на определённый адрес (endpoint), например:

```
GET http://your-server.com/children — получить список детей
POST http://your-server.com/children/1/drink — добавить запись, что ребёнок №1 выпил колу
```

### Объяснение структуры:

**Поле `auth_token`** — секретный токен для проверки, что запросы идут от нашего приложения

**Массив `children`** — список детей с данными:
- `id` — уникальный номер ребёнка (1, 2, 3...)
- `name` — имя ребёнка
- `photo_url` — путь к фотографии (null если не загружена)
- `monthly_limit` — сколько мл добавляется каждый месяц (1000 мл = 1 литр)
- `consumed_this_month` — сколько выпито в текущем месяце
- `remaining` — сколько осталось доступно (накапливается!)

**Массив `drinks_history`** — все записи о выпитом:
- Каждая запись содержит: id записи, id ребёнка, количество мл, дату и время

**Поле `last_reset_date`** — дата последнего пополнения лимитов

## 3. Основная структура приложения

### 3.1. Импорты и создание приложения

В начале файла `main.py` тебе нужно:

**Что такое импорт?**  
Импорт — это подключение готовых инструментов. Например, чтобы работать с датами, нужно импортировать модуль `datetime`.

### 3.2. Настройка CORS

**CORS (Cross-Origin Resource Sharing)** — это механизм безопасности, который позволяет твоему серверу принимать запросы от Android приложения.

Тебе нужно:
1. Импортировать `CORSMiddleware` из `fastapi.middleware.cors`
2. Добавить middleware к приложению с параметрами:
   - `allow_origins=["*"]` — разрешить запросы с любых адресов
   - `allow_credentials=True` — разрешить отправку credentials
   - `allow_methods=["*"]` — разрешить все HTTP методы
   - `allow_headers=["*"]` — разрешить все заголовки

### 3.3. Константы

Создай константы (переменные, которые не меняются):

- `DATA_FILE = "data.json"` — путь к файлу с данными
- `PHOTOS_DIR = "photos"` — папка для фотографий
- `ALLOWED_EXTENSIONS = {".jpg", ".jpeg", ".png", ".webp"}` — разрешённые форматы фото

**Зачем?** Если потом захочешь изменить имя файла или папки, нужно будет изменить только в одном месте.

### 3.4. Создание папки для фотографий

## 4. Система аутентификации

### 4.1. Dependency для проверки токена

Создай функцию `verify_token`, которая будет проверять токен в каждом запросе:

**Название:** `verify_token`  
**Параметры:**
- `authorization: str` — заголовок Authorization из запроса (используй `Header(...)` из FastAPI)

**Что делает:**
1. Загружает данные из `data.json`
2. Получает правильный токен из поля `auth_token`
3. Проверяет, что заголовок Authorization начинается с `"Bearer "`
4. Извлекает токен после `"Bearer "` (удаляет первые 7 символов)
5. Сравнивает токен из запроса с токеном из файла
6. Если токены совпадают — возвращает `True`
7. Если не совпадают — возвращает ошибку 401 (Unauthorized)

**Формат заголовка:**
```
Authorization: Bearer cola_secret_token_2025
```

### 4.2. Как использовать проверку токена

Во всех endpoint-ах (кроме главной страницы) добавь параметр:

```python
authorized: bool = Depends(verify_token)
```

Это автоматически проверит токен перед выполнением функции.

**Параметры:**

**Возвращает:** ничего (None)

**Что делает:**
1. Открывает файл `data.json` для записи

**Подсказки:**

### 5.3. Функция `check_and_update_limits()`

**⚠️ ВАЖНО: Логика изменилась!**

**Название:** `check_and_update_limits`  
**Параметры:** нет  
**Возвращает:** словарь с актуальными данными

**Что делает:**
1. Загружает данные из файла (`load_data()`)
2. Получает текущую дату (`datetime.now()`)
3. Получает дату последнего обновления из `last_reset_date`
4. Сравнивает месяц и год текущей даты с датой последнего обновления
5. **Если месяц или год отличаются** (начался новый месяц):
   - Проходит по всем детям в массиве `children`
   - Для каждого ребёнка:
     - **Обнуляет** `consumed_this_month = 0`
     - **Увеличивает** `remaining` на `monthly_limit` (1000 мл)
     - ⚠️ **НЕ устанавливает** `remaining = monthly_limit`, а именно **прибавляет**!
   - Обновляет `last_reset_date` на текущую дату
   - Сохраняет изменения (`save_data()`)
6. Возвращает данные

**Пример работы:**
```
Январь: remaining = 1000 мл, выпито 300 мл → remaining = 700 мл
Февраль: remaining = 700 + 1000 = 1700 мл (неизрасходованное накопилось!)
```

**Подсказки:**
- Преобразование строки в дату: `datetime.fromisoformat()`
- Получить только дату без времени: `.date()`
- Преобразовать дату в строку: `.isoformat()`
- Сравнение: `.month` и `.year`

**Зачем эта функция?**  
Каждое 1-е число месяца добавляется 1000 мл к остатку. Неизрасходованное накапливается!

### 7.3. Endpoint: Добавить запись о выпитом

**HTTP метод:** POST  
**Адрес:** `/children/{child_id}/drink`  
**Название функции:** `add_drink`  
**Требуется токен:** ✅ ДА  
**Параметры:**
- `child_id: int` — ID ребёнка (из URL)
- `drink: DrinkRequest` — данные о выпитом (в теле запроса)

**Подсказки:**
- Декоратор: `@app.post("/children/{child_id}/photo")`
- Для работы с файлами импортируй `UploadFile`, `File` из FastAPI
- Для сохранения файла используй модуль `shutil` и его функцию `copyfileobj()`
- Получить расширение: `os.path.splitext(file.filename)`
- Проверка расширения: `extension.lower() in ALLOWED_EXTENSIONS`

**Для сохранения файла:**
```python
# Открой файл для записи в бинарном режиме
with open(путь_к_файлу, "wb") as f:
    # Скопируй содержимое загруженного файла
    shutil.copyfileobj(file.file, f)
```

### 7.7. Endpoint: Получить фотографию

**HTTP метод:** GET  
**Адрес:** `/photos/{filename}`  
**Название функции:** `get_photo`  
**Требуется токен:** ❌ НЕТ (публичный доступ к фото)  
**Параметры:**
- `filename: str` — имя файла (например, `child_1.jpg`)

4. Возвращает файл (используй `FileResponse` из FastAPI)

**Пример запроса:**

GET http://your-server.com/photos/child_1.jpg
```

**Пример ответа:**
```

```

**Подсказки:**
- Декоратор: `@app.get("/photos/{filename}")`
- Для проверки существования файла: `os.path.exists(путь)`

## 12. Что делать, если возникли проблемы

### Сервер не запускается

**Проблема:** `ModuleNotFoundError: No module named 'fastapi'`  
**Решение:** Установи FastAPI: `pip install fastapi uvicorn python-multipart`

**Решение:** Порт 8000 занят. Используй другой порт: `--port 8001`

**Решение:** Проверь синтаксис и отступы. В Python отступы критичны!

**Проблема:** `FileNotFoundError: data.json`  
**Решение:** Создай `data.json` в той же папке, где `main.py`

**Проблема:** `JSONDecodeError`  
**Решение:** Проверь `data.json` на jsonlint.com

**Решение:** Проверь, что вызываешь `save_data()` после изменений

**Проблема:** Счётчики не обновляются

### Проблемы с аутентификацией

{
  "message": "Запись добавлена",

    "id": 1,

  }

Response 404: Ребёнок не найден
Response 401: Unauthorized
```

#### 3. Получить историю ребёнка
```
GET /children/{child_id}/history
Authorization: Bearer {token}

Response 200:
[
  {

    "amount_ml": 330,
    "timestamp": "2025-01-13T14:30:00"
  }

Response 401: Unauthorized

DELETE /drinks/{drink_id}

Response 200:

    "id": 1,
    "child_id": 1,
    "amount_ml": 330,
    "timestamp": "2025-01-13T14:30:00"
  }
}

Response 404: Запись не найдена
Response 401: Unauthorized
```

```
POST /children/{child_id}/photo

Form Data:

Response 200:
{

  "photo_url": "photos/child_1.jpg",
  "child_id": 1

Response 400: Неверный формат файла

```

### Коды ошибок
- **200** — Успех
- **400** — Неверный запрос (например, неподдерживаемый формат фото)
- **401** — Не авторизован (неверный или отсутствующий токен)
- **404** — Не найдено (ребёнок или запись не существует)
- **500** — Ошибка сервера
